# TkBuilder v2 – product & engineering spec

> **Scope rule (from the user): keep it focused and easy.** Everything must
> serve the original idea - drag & drop widgets that snap into place, fill out
> actions without code, generate Python - plus themes and easy ways to get
> values in and out of the GUI for engineers. No feature creep: prefer fewer,
> better, obvious features over many. Every screen must be understandable by
> a first-time user without reading docs.

**Goal:** a professional, polished desktop tool that lets an **engineer** (or a
non-programmer) build a Tkinter front end for **existing Python code** in
minutes: drag widgets in, wire them to their own functions without writing GUI
code, pick a theme, and export clean, maintainable Python. It must feel like a
finished commercial product: smooth, consistent, fast, with no rough edges.

Pure Python 3.8+ stdlib (the generated app must run with the standard library only).
Dev machine: Windows 11, Python 3.12. **Creating native windows is slow on this
machine (~15–20 ms each)**: avoid needless widget creation/destruction
everywhere (reuse, update in place, lazy-build).

v1 (`SPEC.md`) describes the existing architecture; v2 extends it. Read both.
The v1 code is committed in git (`git log`), so you can diff against it.

## 1. Shared foundation (lead-owned, read-only for agents)

| File | What |
|---|---|
| `model.py` | Data model v2: `WIDGETS` (new: FilePicker, Table, Console), `ACTIONS` (new: call_function, run_command, log, timers, tables…), `SETTINGS_SPECS`, hooks, copy/paste, migration from v1. **Read it fully.** |
| `tkmap.py` | Node → widget class / options / style name / initial state, for designer *and* codegen. |
| `apptheme.py` | App themes: `THEMES`, `THEME_ORDER`, `VARIANTS`, `style_ops(theme, size)`, `tk_colors(theme, kind)`, `rename_style(name, prefix)`, `base_theme()`. |
| `introspect.py` | Read a user's .py with `ast` (no execution): `list_functions`, `signature_text`, `module_name_for`, `find_module_file`, `param_widget_hint`. |

Agents must not edit these. If you need a change, implement a local helper and
list the request in your report (the lead integrates). Small obvious bugs:
report them precisely.

Key concepts:
* **Settings** `project.settings`: app_name, theme, font_family, font_size,
  dpi_aware, code_style (`split`|`single`), backend_dir, threads. Also
  non-spec keys the shell may store: `export_dir` (relative to the project file
  when possible).
* **ctx** = `tkmap.make_ctx(project.settings)` → `{"theme", "size"}`.
* **Fonts**: tuples whose first element is `apptheme.FAMILY` mean "the app font
  family" = settings font_family, or the platform default (`Segoe UI` on
  Windows; generated code: `tkfont.nametofont("TkDefaultFont").actual("family")`).
* **Layout**: one system only - the snapping **grid** (row/col/span/fill/
  align/pad, `sticky_for`, `grid_weights`). `model.layout_mode()` is "pages"
  for a Notebook (children are Tabs) and "grid" for everything else.
* **Hooks**: `node["hooks"]` = event keys that also call the user's own method
  `model.hook_name(node, event)` e.g. `on_button1_clicked`. Buttons have the
  click hook on by default. Menu items: `item["hook"]` → `model.menu_hook_name`.
* **Variants** ("Look"): `props["variant"]`, values from `apptheme.VARIANTS[cls]`.

## 2. Generated code (agent A2: `codegen.py`, `codeview.py`, `test_codegen.py`)

### 2.1 Layout of the output
`codegen.generate(project) -> dict {filename: source}`; plus
`codegen.generate_single(project) -> str` (one file) and
`codegen.export(project, folder, overwrite_user_code=False) -> report dict`
(`{"written": [...], "kept": [...], "missing_hooks": [stub source...]}`).

**split** (default, recommended for engineers):
* `<base>_ui.py` – regenerated every export. Header: "Generated by TkBuilder –
  do not edit, your changes would be lost. Put your code in <base>.py".
  Contains `class <Class>UI(tk.Tk)` with all widgets, designed actions, the
  runtime API and empty hook methods.
* `<base>.py` – created **only if it doesn't exist**. `class <Class>(<Class>UI)`
  with a stub for every enabled hook (body: a helpful comment showing how to
  use `self.get/set` for the widgets nearby + `pass`) and
  `if __name__ == "__main__": <Class>().mainloop()`. If it exists, it is never
  touched; `missing_hooks` lists stubs for hooks it doesn't define yet (check
  with `ast`), so the UI can offer "copy to clipboard".

**single**: one file `<base>.py` with `class <Class>(tk.Tk)` containing
everything, hooks included (with TODO comments).

Base/class names: `project.module_basename()`, `project.class_name()`.

### 2.2 Runtime API (in the UI class; documented with docstrings + a short
"How to use" comment block at the top of the class)
```
get(name)                 typed value of a widget (see table) / radio group by group name
set(name, value)          set a widget's value (thread-safe: may be called from any thread)
values(window=None)       {name: value} of every input widget (+ radio groups by group name)
set_values(mapping)       set many at once
widget(name)              the real tk widget (for advanced use)
on(name, event, callback) connect your own function: event = "click"/"change"/"select"/
                          "enter"/"double_click"/"tab_change"; callback() takes no args
log(text, console=None)   add a line to a console (first Console if None); thread-safe
run_in_background(func, *args, on_done=None, on_error=None, busy=None, sender=None, **kw)
                          run func in a thread; on_done(result)/on_error(exc) run in the GUI
                          thread; busy = Progressbar name (indeterminate while running);
                          sender = widget name disabled while running
call_in_gui(func, *args)  schedule func in the GUI thread (from worker threads)
show_info(msg, title) / show_error(msg, title) / ask_yes_no(msg, title)
open_window(name) / close_window(name)
```
Typed values: Entry → str / int / float per `value_type` (invalid number →
`ValueError` with a friendly message naming the field); Spinbox → int if
decimals==0 else float; Scale → number rounded to resolution; Checkbutton →
bool; Radiobutton → group value; Combobox → str/typed; Listbox → str (or list
when "many"); Table → selected row as dict {column title: value} (list of dicts
when "many", None if none); Text/Console → str; Label/Button → text;
Progressbar → number; FilePicker → path str; Notebook → visible tab title.
`set` accepts the same plus: Table ← list of rows (lists/tuples/dicts by
column title); Listbox/Combobox ← list replaces items, str selects;
Console ← str replaces.
Widgets in closed secondary windows: `get` returns the last known/starting
value, `set` is remembered and applied when the window opens (no crash).

### 2.3 Other generation rules
* Theme: `_setup_theme()` applies `apptheme.style_ops` (+ `tkmap.custom_style_ops`
  per widget) as literal `style.configure/map(...)` and `option_add` lines;
  `theme_use(base)` with a fallback to "clam" if the theme isn't available;
  FONT_FAMILY resolved at runtime when settings font_family is "".
* DPI: if settings dpi_aware, call `ctypes.windll.shcore.SetProcessDpiAwareness(1)`
  (guarded, Windows only) before creating the Tk root.
* Window: title, geometry, centred/maximized start, min size, resizable,
  topmost, icon (`iconphoto` for png/gif, `iconbitmap` for .ico; missing file →
  skip silently), padding, menu bar (+ shortcuts shown with `accelerator` and
  bound), timer (`timer_ms` → on_timer actions + hook; no overlapping ticks
  while a background call from the previous tick is still running).
* Widgets: tkmap everywhere; small helper classes emitted only when used
  (FilePicker, Tooltip, Entry placeholder); scroll wrappers; Scale value
  label; Table columns, stripes (`tag_configure` odd/even using theme
  colours), rows.
* Actions: every action in `model.ACTIONS`. `call_function`: builds kwargs/args
  from `args` (source widget → `self.get(id)`, value → the literal, all →
  `self.values()`), runs in background if `background` (settings `threads` is
  the default for new actions), applies result per `result` mode, and **the
  remaining actions of the same event run after the call completes** (inside
  on_done). Errors → message if `show_errors` + traceback to console/log.
  Module import is guarded so the app starts even if the backend module is
  missing; using it then shows a clear error. `backend_dir` →
  `sys.path` insert (relative to the generated file when possible).
  `run_command`: subprocess with output streamed line-by-line to the target
  (thread + queue), busy progress, error message on non-zero exit if wanted.
* Keep the generated code short and obvious: a beginner engineer must be able
  to read the UI file top to bottom. Helpers only when used.
* Placeholders `{widget_id}` → f-strings with `self.get(...)`.
* Hooks: handler runs designed actions, then `self.<hook>()`.
* Code quality: PEP 8, readable names, docstrings, friendly section comments,
  no unused imports, deterministic output (same project → same code).
* `test_codegen.py`: every widget type, every action, both code styles, every
  theme, grid + tabs layouts, menus, timers, hooks, background calls
  with a real backend module written to a temp dir (wait for threads by
  pumping `update()`), `export()` keep-user-file behaviour, missing backend.
  All with `TKBUILDER_NO_DIALOGS=1` stubs, short-lived windows.

### 2.4 CodeView → "Export" window
Tabs for each generated file (syntax highlighted, line numbers, read-only),
code-style switch (split/single), folder chooser + "Export" (uses `export()`,
shows written/kept files, offers missing hook stubs with Copy), "Copy",
"Open folder". Remembers `settings["export_dir"]` via the app (commit).

## 3. Designer (agent B2: `workplane.py`, `palette.py`, new `preview.py`)

* **Theme-accurate preview** of any `apptheme` theme: preview styles via
  `apptheme.rename_style(name, prefix)` with layouts/elements copied from the
  theme's base (generalise the existing `install_preview_styles`), then apply
  `style_ops` + `custom_style_ops` to the renamed styles. One prefix per theme
  (cache). Classic tk widgets get `tkmap` colours. The fake window frame
  (title bar etc.) follows light/dark of the theme. Switching theme in settings
  re-renders instantly.
* **Smooth drag & drop (no layout jumps):** never insert placeholder widgets
  into the design while dragging. Compute targets from geometry (`grid_bbox`,
  child bboxes) and draw **overlay** indicators (insertion bars, cell
  highlight, container outline, "new row/column" strips just outside the
  grid) on a transparent-ish overlay (placed frames or a toplevel canvas).
  Indicators **animate** (ease 60–100 ms) between positions. Ghost = a small
  semi-transparent toplevel showing a *real rendered preview* of the widget
  (alpha ~0.85) + its name. Auto-scroll near edges. Esc cancels. Drop
  animates the widget into place (brief highlight flash).
* **Span handles:** a small handle on the right/bottom edge of the selected
  widget; dragging it changes colspan/rowspan, snapping cell by cell with a
  highlighted preview. Faint grid lines of the target container while dragging.
* **Copy / cut / paste** of the selected widget (`project.copy_nodes/paste`,
  system clipboard text) - paste goes below the selection or into the selected
  container.
* Keep everything from v1 (inline edit, context menu, tab hover switching,
  window bar, resize grip, inert widgets, incremental refresh).
* Palette: categories `model.PALETTE_CATEGORIES` with `CATEGORY_TITLES`,
  polished cards with icon badges, search, drag/click, favourites (optional).
* Previews of the new widgets: FilePicker (entry + button), Table with
  headings (and a couple of greyed sample rows if empty), Console (log look
  with greyed sample text if empty).

## 4. Inspector & dialogs (agent C2: `inspector.py`, `outline.py`, `dialogs.py`, new `settingspage.py`)

* **Performance first:** selecting another widget of the same type must
  update editor values in place (no rebuild); cache one page per widget type
  (lazily built); target < 100 ms for selection changes on this machine.
* Project **Settings page** (shown for `show(None)` / "App settings"): all
  `SETTINGS_SPECS`; **theme gallery** = grid of cards drawn on one Canvas
  (mini mock-up in the theme's colours + name), click to apply live.
* Property editors for new kinds: `variant` (combobox of VARIANTS labels),
  `columns` (table editor: title/width/align, add/remove/reorder), `rows`
  (grid/CSV editor), `shortcut` (capture a key press), `image` incl. .ico for
  windows. "More options" collapsible group for `advanced` props.
* Layout tab: `LAYOUT_SPECS` with a clear visual (keep it simple).
* **Actions tab:** per event: actions list + **"Also call my code:
  on_x_clicked()"** checkbox (hooks) + "Copy method" button.
* **Function picker** for `call_function` (dialogs.py): choose a .py file
  (default folder: settings backend_dir / project folder), list functions with
  signature + docstring (`introspect`), map each argument to a widget (combobox
  with suggested matches by name) or a literal value or "all values", result
  mode + targets, background/busy/errors options. Buttons **"Create inputs for
  me"** (adds a Group Box with Label+input per argument using
  `param_widget_hint`, wired automatically) and **"Create result labels"**.
  `run_command` gets a friendly form with live preview of the command line.
* **"Code" tab** for the selected widget: copyable snippets of the generated
  API for it (`value = self.get("name")  # float`, `self.set(...)`, hook
  method stub) – teaches engineers how to use the output.
* Outline: icons, filter box, right-click menu.

## 5. Shell & editor UX (agent D2: `app.py`, `theme.py`, `startpage.py`, `prefs.py`, `make_examples.py`, `examples/`, `README.md`)

* **Editor theme** light/dark (prefs). `theme.py` palettes with the same

  notification), `prefs` dict.
* Start page (when no project is open / File ▸ New): New blank, templates
  (engineering examples), recent files, open.
* Recent files, autosave every 60 s to `%APPDATA%/TkBuilder/autosave.tkb` +
  recovery offer on next start, preferences dialog, about, F1 shortcuts help.
* Run My App: if `export_dir` has the user's `<base>.py`, regenerate the UI
  file there and run the user's file (so their backend code runs); otherwise
  run a temp export. Errors show nicely (traceback in a scrollable dialog).
* CLI: `python app.py --export project.tkb [folder]` regenerates without GUI.
* Examples (all must generate & run): Beam calculator (call_function → dict
  → labels), Unit converter, Live sensor readout (timer + read_sensor →
  label/progress), Simulation runner (background + progress → table),
  Script runner (run_command → console), plus the 4 v1 examples upgraded. Backend: `examples/backend/engineering.py`.
* Keep `TKBUILDER_NO_DIALOGS=1` test mode working (see README).

## 6. Rules for everyone
* Plain-English UI text; professional, consistent spacing (8 px rhythm),
  alignment, typography (`theme.UI_FAMILY`), icons.
* Never block on dialogs in tests: always `TKBUILDER_NO_DIALOGS=1`, `timeout`,
  destroy windows, `app.dirty = False` before destroy. Never leave processes.
* Screenshots: `PIL.ImageGrab` fails here; use the PrintWindow helper at
  `<scratchpad>/pwshot.py` (`pwshot.grab(toplevel, path)`), view with Read.
  Use **forward slashes** in Python string paths in heredocs.
* Don't edit files you don't own; other agents work in parallel.
* Report: what you built, test evidence, known gaps, requests for shared files.

## 7. High-DPI rule (decided during v2)
The user's screen is 4K at 250 %. The editor is DPI-aware (`theme.SCALE`,
`theme.px(n)`). When `settings["dpi_aware"]` is on (default), generated apps
compute `SCALE = winfo_fpixels("1i") / 96` (>= 1) and wrap every pixel size in
`px(n)`: geometry, min size, padx/pady, padding, wraplength, lengths, table
column widths / row height, canvas sizes. The designer scales its preview by
the same factor so the designed window appears at the real app's size. Fonts
scale through Tk automatically. Editor panels use `theme.px()` for their own
pixel sizes.
